Рекомендую **целевой мир ~360 x 360 м (R≈180), вводимый ступенями**: фазы 1-3 живут в R≤120 (вариант «220 м»), фазы 4-8 расширяют карту до 360 м. ### Иерархия существующих дорог (что считается «исторической»)
Узкие улочки 1,7-1,8 м (мастер-сетка, дороги этапов, артерии районов) = «старый город», как в средневековом ядре; кольцо r57,4 (5,6 м) = единственная «магистраль». Новые дороги **не расширяют и не перекладывают** старые: ядро остаётся узким, снаружи современные ширины. Это и жанрово (старый центр + широкие кольца) и безопасно для сигнатур.

## (h) Интеграция с кодом (дизайн)

1. **Отдельный слой.** `assets/masterplan-v161.js` (грузить после `late-game-v161.js`, перед основным скриптом) + `assets/masterplan-data-v161.js` (JSON плана одной строкой). API: `MasterplanV161.pads()`, `.build(padId)`, `.restore(state)`, `.enabled`. Все меши в группе `mp161Net` (без слова «road»; не `v70RefinedServiceRoads`, не `v113UnifiedStarterRoadSurface`, не `cityWorldRuntime.stageRoads`) - сигнатуры дорог 17/678830722, 47/-510574045, OLD_SAVE 51/648310607 считаются по этим трём именам (см. `tests/world-consistency.test.mjs:32-46`) и не меняются.
2. **Стыковка только через узлы** (`nodes[].existing`): 7 узлов на кольце-1 и 4 узла хабов. Узел - кружок/плита поверх существующего кольца (отдельный меш y=+0,02), кольцо не пересобирается.
3. **Дороги не перекладываются при апгрейдах**: слой хранит `built[padId]` в сейве (`planV161` в `tycoon3d_save_v3`, миграция: у старых сейвов фазы закрыты, **их мир не меняется**; новые кружки появляются только при достижении ворот), сборка идемпотентна по `padId + версия данных`.
4. **Свежий мир остаётся пустым**: нет кружков плана, пока не построен этап-ворота 1; ручная укладка первых дорог по секциям без изменений.
5. **Коллизии / пути**: каждая дорога плана регистрирует в реестре v83 только невидимо-нужное: бордюры/мосты как тонкие боксы; здания лотов - коллайдеры по реальному контуру (4 бокса/здание, как `houseV161`), двери смотрят на улицу (`lots[].door`, `lots[].normal`). Машины/NPC: граф `nodes + edges` плана подключается к существующему маршрутизатору **как дополнительный граф** (`projectToRoad` не трогаем); трамвай/автобус/поезд - фоновые, по полилинии, пул <= 2 на линию, лимит ambient-транспорта общий.
6. **Формат данных** (`plan-A.json`): `land`, `water[]`, `roads[]` {id, cls, w, pts, level, phase, joins[], bridge, tram, bus}, `nodes[]` {id, type, x, z, r, existing}, `rails[]`, `stations[]`, `districts[]`, `lots[]` {c, p[4], door, k, f}, `pads[]`, `keepout[]`, `check`. Из него считаются и рисуются схемы (`gen.mjs`) и тесты.
7. **Тесты (план):** связность (0 изолированных, одна компонента вместе с E-RING), нет тупиков (кроме `terminal`), число рук узла = число входящих дорог, лоты не пересекаются с дорогами/рельсами/водой/keepout, каждый лот имеет дверь на улицу, ни одного меша плана до оплаты кружка, сигнатуры 17/47/51 без изменений, два запуска на свежем и OLD_SAVE, потолок мешей и draw calls на камере `CAM_MAX_DIST`. Уже сейчас `gen.mjs` считает связность, тупики и дубликаты id (`plan.check`): план A: **1 компонента, 0 тупиков, 0 изолированных, 5 близких лотов** (лоты на углах, к допуску в реализации); B: 1 компонента, 2 тупика (диагональные съезды трубы, будет подогнано).
8. **Бюджет и LOD**: чанки 60 м, `InstancedMesh` для лотов, слитые дороги, дальний LOD - силуэты кварталов одним мешем на сектор; чанк строится при оплате кружка и приближении <= 150 м, выгружается при удалении > 200 м (геометрия освобождается, без утечек). Целевой потолок описан в (a).
