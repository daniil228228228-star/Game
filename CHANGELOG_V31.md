  растущая дорожная сеть) практически отсутствует — есть только именной скелет

- Составлен и отправлен пользователю roadmap из этапов A–G (жилой город →

## 2026-09-20 — Этап A, срез 1: «жилой город» — население как ресурс, первое жилое здание, районы с реальными статами

- **Население (`population`)** стало настоящим отслеживаемым ресурсом:
  `cityState.population` хранится в сейве (как `money`/`planks`/`concrete`),
  показывается в HUD новым чипом `🏘️ N/CAP` рядом с деньгами/досками/бетоном/
  металлом. Растёт/убывает простым lerp'ом к вместимости жилья
  (`updatePopulation()`: `population += (capacity - population) * 0.15`),
  тикает раз в секунду вместе с остальной городской симуляцией (переиспользован
  существующий `cityTickAccumulator` в `updateCityExpansion()`, никакой новой
  per-frame логики) — намеренно без модели спроса/предложения, это задел для
  этапа D.
- **Первое настоящее жилое здание**, отдельное от производственной спирали
  `STAGES`: `RESIDENTIAL_BUILDING` («Жилой дом» / Apartment Block, +60 к
  вместимости населения). Строится через панель «Город и развитие»
  (`renderCityPanel()`), кнопка в карточке района «Жилой район» — стоит
  650 💰 + 4 🪵, 4.5с стройки. Визуально стройка идёт по-настоящему: вызывается
  тот же `spawnConstructionSite()`, что и для зданий спирали (кран, экскаватор,
  бетономешалка), но НЕ регистрируется в `growingMeshes`/`STAGES`-индексации —
  рig анимируется и сам себя убирает через уже существующий
  `updateConstructionSites()` (он умеет работать без `buildRef`), поэтому
  никакой код спирали не тронут. По завершении на сцену добавляется настоящее
  здание через переиспользованный `createBuildingMesh()` (archetype `office`,
  тёплый терракотовый цвет вместо офисного синего стекла — с балконами).
  Место под здание ищется рядом с хабом района «suburb» с обязательной
  проверкой `distToNearestRoadSegment()` (та же защита от «декор/здание легло
  на дорогу», что уже используется для рассыпанного по карте декора) —
  подтверждено численно в тесте (см. ниже), а не только скриншотом.
- **`CITY_DISTRICTS` получили реальные статы** вместо плоского
  unlock-уровня: `cityState.districtStats[id] = { population, satisfaction }`
  — 2 числа на район, обновляются раз в секунду в новой `updateDistrictStats()`
  от уровня района (существующий механизм апгрейда) и факта постройки жилья;
  не скрытая тяжёлая симуляция, просто сглаживание к цели. Показывается в
  каждой карточке района в панели «Город и развитие», на ru и en.
- `saveVersion` 19 → 20. В `load()` добавлена миграция: у старых сейвов без
  `cityState.population`/`.housing`/`.districtStats` эти поля получают
  дефолты (0 / `{apartmentBlockBuilt:false}` / `{population:0,satisfaction:50}`)
  — без падений, по тому же паттерну, что и остальные поля `cityState`.
- Не тронуто: `STAGES`, `growingMeshes`, `constructionQueue`, pad-механика
  основной спирали построек, весь слой fleet/base/contracts/tenders/
  `COMPANY_TIERS`/`CLIENT_TIERS` — только читались как референс.
- Проверено headless Chromium через Playwright (`chromium.launch` с
  `--use-gl=swiftshader`, вьюпорт 900×600): чистый boot без консольных
  ошибок; постройка жилого дома → чип населения растёт от 0 к 60 за
  несколько секунд; численная проверка клирэнса (`THREE.Box3` + четыре угла
  бокса здания через `distToNearestRoadSegment()`) — минимальное расстояние
  до дороги ~24 (порог 2.6, дом стоит у suburb-хаба в углу карты, далеко от
  спирали дорог); старый сейв (сконструирован вручную, `saveVersion: 19`, без
  `population`/`housing`/`districtStats`) загружается без ошибок с
  корректными дефолтами и сохранённым старым прогрессом (деньги, репутация,
  уровни районов); апгрейд района и запуск городской стратегической
  инициативы (существующие, нетронутые механики) по-прежнему работают;
  переключение языка ru/en пересобирает подписи жилого здания без ошибок.

## 2026-09-20 — Этап A, срез 2: «жилой город» расширен на несколько районов

- **Жильё стало доступно в нескольких районах**, не только в suburb:
  `cityState.housing` из единственного плоского объекта среза 1 стал объектом
  по районам — `{ suburb, business, waterfront }`, каждый со своим
  `{apartmentBlockBuilt, pendingUntil, pos}`. `industrial` намеренно без
  жилья (тематически промзона, не жильё). Выбран вариант (a) из ТЗ —
  несколько экземпляров существующего `RESIDENTIAL_BUILDING`, а не второй
  тир апгрейда — прямое обобщение конвейера среза 1 вместо второй системы.
  Кнопка «Построить жилой дом» теперь есть в карточке любого из трёх районов
  панели «Город и развитие», как только район разблокирован (та же
  `districtUnlocked()`), поэтому за игру реально строится до 3 отдельных
  видимых 3D-зданий вместо одного.
- **Размещение** каждого нового здания ищется обобщённой версией функции
  среза 1 — `residentialBuildingPosition(districtId)`, кольцевой перебор
  вокруг хаба конкретного района с той же проверкой
  `distToNearestRoadSegment()`. Добавлена проверка на непересечение
  жилых зданий друг с другом (`BUILDING_CLEAR = 6`) — простая дистанционная
  проверка по образцу уже существующего decor-скаттера против
  `stagePositions` (`createGroundMicroDetail()`).
- **Население расширено на 2 района**: `updateDistrictStats()` теперь лерпит
  население отдельно для каждого района с построенным жильём
  (`suburb`/`business`/`waterfront`) тем же коэффициентом 0.15/с, что и в
  срезе 1 (был только suburb). `cityState.population` (HUD-чип) — сумма по
  всем районам. `cityState.districtStats[id]` трёх районов показывает
  реальное различное ненулевое население после постройки жилья в каждом,
  видно в панели «Город и развитие» на ru/en.
- Видимый рост города — сами 2-3 дополнительных жилых здания в разных углах
  карты, без дополнительных визуальных систем (например, подсветки окон)
  — осознанно достаточно для этого среза.
- `saveVersion` 20 → 21. В `load()` добавлена миграция: сейв `saveVersion`
  20 с плоским `cityState.housing` (`{apartmentBlockBuilt,pendingUntil,pos}`,
  всегда про suburb) превращается в `housing.suburb`, `business`/
  `waterfront` получают дефолт «не построено»; более старые сейвы без поля
  `cityState.housing` вовсе получают дефолт для всех трёх районов — по
  тому же паттерну, что и миграция среза 1.
- Не тронуто: `STAGES`, `growingMeshes`, `constructionQueue`, pad-механика
  основной спирали построек, весь слой fleet/base/contracts/tenders/
  `COMPANY_TIERS`/`CLIENT_TIERS` — только читались как референс. Тик
  по-прежнему раз в секунду через существующий `cityTickAccumulator`
  (`updateCityExpansion()`), никакой новой per-frame логики.
- Проверено headless Chromium через Playwright (`chromium.launch` с
  `--use-gl=swiftshader`): чистый boot без консольных ошибок; постройка
  жилья в suburb/business/waterfront → население всех трёх растёт
  независимо к своей вместимости (60 каждое, 180 суммарно); численная
  проверка клирэнса (`THREE.Box3` + углы + центр через
  `distToNearestRoadSegment()`) для всех трёх зданий — минимум ~3.4-24
  (порог 2.6); численная проверка непересечения зданий друг с другом —
  минимум ~72 (порог 6); старый сейв со сплюснутым `housing`
  (сконструирован вручную, `saveVersion: 20`, точно в формате среза 1)
  загружается без ошибок, мигрирует в `housing.suburb`, business/waterfront
  — дефолт; ещё более старый сейв без `cityState.housing` вовсе
  (`saveVersion: 19`) — все три района дефолт, 0 населения, без падений;
  переключение языка ru/en пересобирает все построенные жилые здания и их
  подписи без ошибок; панели fleet/base/tenders/contracts/systems/city
  по-прежнему рендерятся без ошибок (`renderFleetPanel`, `renderBasePanel`,
  `renderTendersPanel`, `renderContracts`, `renderSystemsPanel`,
  `renderCityPanel`, `renderOperationsPanel`, `renderFleetOperations`,
  `renderStaffPanel`).
