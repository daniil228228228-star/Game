# Changelog — Tycoon v161

## 2026-10-03 (5) — адаптер Yandex Games SDK (`assets/yandex-platform.js`)

**Что сделано.** Один новый файл `assets/yandex-platform.js` (подключён `<script src>` сразу после `development-core-v160.js`, до игрового кода; `tools/standalone.mjs` его
бандлит сам, `tests/bundle.test.mjs` проходит) определяет `window.TycoonPlatform` с теми же именами, что вызывают существующие обёртки (`tycoon-v161.html:9182-9197`, `:9361`):
`showInterstitialAd()`, `showRewardedAd(reason)`, `cloudSave(data)`, `cloudLoad()`, `submitLeaderboardScore(score)`. Методы появляются только после успешного `YaGames.init()`,
поэтому `rewardedAvailable()` остаётся `false`, пока SDK не готов. В игре изменена одна строка: `animate()` (`:14381`) выходит, пока `TycoonPlatform.paused`. Панели и покупка flatbed не тронуты.
- **Активация** только если `location.hostname` содержит `yandex` или в URL `?yandex=1`; иначе скрипт ничего не делает (TycoonPlatform остаётся `{}` от игры, как раньше).
  SDK грузится лениво с `/sdk.js` (без CDN); если `window.YaGames` уже есть (тест) — не грузится.
- **Реклама:** rewarded — награда только если сработал `onRewarded` (промис резолвится на `onClose`; `onError` = `false`), interstitial — `wasShown`. Все методы возвращают boolean
  (обёртка игры считает любой truthy-результат успехом, поэтому объект `{ok:false}` дал бы награду — намеренно не используем). Одна реклама за раз, страховочный таймер 180 c.
- **Пауза/звук на время рекламы и `game_api_pause/resume`:** игровой флаг `muted` (прежнее значение возвращается, localStorage не трогается) + `audioCtx.suspend()`,
  остановка рендер-цикла через `TycoonPlatform.paused`, `GameplayAPI.stop/start`. `LoadingAPI.ready()` — один раз, после 2-го кадра (или через 20 c).
- **Облако:** `localStorage` остаётся источником правды. Выгрузка `player.setData({save,savedAt})` не чаще раза в 60 c и при уходе со вкладки, лимит 190 КБ. Загрузка при старте:
  облако подменяет локальное и страница перезагружается один раз (с подавлением автосохранения, защита от цикла через sessionStorage), только если локальный сейв отсутствует/пустой
  (stage 0, нет зданий) или его `savedAt` старше облачного более чем на 2 c. Локальный сейв без `savedAt` (старый формат) никогда не перезаписывается — только выгружается. Формат сейва не менялся.
- **Лидерборд:** `getLeaderboards().setLeaderboardScore('tycoon', score)`, имя можно задать `window.TYCOON_YANDEX_LEADERBOARD`; для неавторизованных игроков (`getMode()==='lite'`) молча пропускается.
  Раз в 60 c автоматически отправляется `stats.totalEarned`, если он вырос за сессию.
- Все вызовы SDK обёрнуты в try/catch, сбой SDK не ломает игру.

**Тесты.** `tests/platform.test.mjs` (2 запуска игры, поддельный `YaGames`): `ready` ровно один раз; награда только в `onRewarded`, не при `onError`/закрытии без награды; звук выключен и цикл
стоит во время рекламы, восстановлены после (в т.ч. прежнее «звук выключен» сохраняется); `game_api_pause/resume`; формы ответов cloud/leaderboard; правила восстановления из облака; без `?yandex=1`
платформа инертна и SDK не трогается. Также прогнаны `boot` и `old-save` (оба зелёные); полный `npm test` не запускался.

**НЕ проверено (нужен настоящий SDK/консоль):** реальные сигнатуры и тайминги колбэков на платформе; полный список доменов (проверка по подстроке `yandex` в hostname, а не по списку);
требования модерации (в т.ч. к рекламе, кнопкам rewarded, звуку при показе рекламы); локализация текстов рекламы/бонусов (язык из `ysdk.environment.i18n` не подключён, игра берёт свой `lang`);
реальный перезапуск при восстановлении облака на устройстве с другим прогрессом; лимиты частоты `setData`/лидерборда; автоматически interstitial нигде не показывается (размещение — решение разработчика).
Лидерборд `tycoon` должен существовать в консоли, иначе отправка тихо вернёт `false`. Отправка `totalEarned` может занизить результат после престижа/сброса (SDK хранит последний, а не лучший счёт).

**Чек-лист для консоли Yandex Games:**
1. Собрать single-file: `node tools/standalone.mjs build tycoon-v161.html dist/tycoon-v161-standalone.html`, залить как `index.html` в ZIP (без внешних ссылок; `/sdk.js` подставляет платформа).
2. В черновике проверить в iframe платформы: загрузка, `LoadingAPI.ready`, пауза/звук при рекламе, rewarded-бонус на 3 вида наград, отсутствие рекламы при обычной игре.
3. Создать лидерборд с именем `tycoon` (или задать своё имя через `TYCOON_YANDEX_LEADERBOARD`) — и включить авторизацию для проверки.
4. Проверить облачное сохранение на двух устройствах/аккаунтах (прогресс подтягивается, локальный не теряется), размер данных < 200 КБ.
5. Проверить русский и английский интерфейс, портретную/горизонтальную ориентацию, мобильные браузеры.
6. Пройти требования модерации консоли (иконка, обложка, описание, возрастной рейтинг) и отдельно проверить, что игра не требует рекламу для прогресса.
Прогонов игры: 4 (platform x1 = 2 запуска, boot, old-save).

## 2026-10-03 (4) — «дорога не перекладывается после апгрейда»: закрыт KNOWN ISSUE roads

**Симптом (из `roads.test.mjs`):** любой не дорожный апгрейд базы (проверено на «Офис», `buyBaseUpgrade('office')`) пересоздавал 24 из 38 road-мешей и слой
`v113UnifiedStarterRoadSurface`, раскладка при этом побайтово та же.

**Корневая причина (замерено перехватом `Object3D.prototype.remove` со стеком, 1 прогон):** `buyBaseUpgrade` -> `refreshBaseWorld(true)`, который обёрнут слоем v84
(`tycoon-v161.html:33174`, `scheduleSync(true)` -> `fullSync`). `fullSync` на каждый вызов делает два полных пересоздания без проверки результата:
1. `refreshAccessRoads()` (v84, `:33075`) всегда сносил и заново строил группу `v84RegistryAccessRoads` (13 вызовов `remove`);
2. `window.__TYCOON_V61_AUDIT__.refresh` -> `refresh()` слоя v86 (`:33680`) сносил `v86CanonicalStageRoads` и через `markings.apply` -> `rebuildRoadUnion` (`:34058`)
   — унифицированную поверхность. Его защита (`lastStageRefreshGenV116` / `generation` из `ensureSig()`) смотрит на реестр коллизий, а новый «Офис» — это новая запись
   `base` в реестре, поэтому `generation` честно растёт, хотя дороги не меняются.
Цепочка v113 (`syncAll`) тут ни при чём: она добавляет только новые стадии; v116-патч `invalidate` теперь no-op, но raw `refresh` вызывается напрямую из `fullSync`.

**Исправление (приём v116: сигнатура реальных входов/результата, в том же владеющем месте, новых слоёв нет):**
- `roadGroupLayoutSigV161(g)` (`:32840`, в v84; экспортирована как `window.__TYCOON_ROAD_LAYOUT_SIG_V161__`): тип геометрии, число вершин, контрольная сумма позиций,
  цвет материала и `matrixWorld` каждого меша группы.
- `refreshAccessRoads` (`:33076-33095`) и `refresh` v86 (`:33680-33690`) сначала строят новую группу, считают подпись и сравнивают её с подписью, **сохранённой в
  `userData.v161LayoutSig` при создании предыдущей группы** (живые меши сравнивать нельзя: поздние слои дописывают разметку/скрывают источники объединения — первая версия
  сравнения по живым мешам не сработала, см. прогон ниже). Совпало — новая группа утилизируется, старые меши, разметка и объединённая поверхность остаются;
  не совпало (или у старой группы нет подписи) — прежний путь «снести и построить».

**Замеры (один и тот же сейв: OLD_SAVE + 6 домов через `purchaseCurrentPad()`, затем Офис):**
| | до | после |
|---|---|---|
| road-меши уничтожено / создано после Офиса | 24 / 24 | 0 / 0 |
| `v113UnifiedStarterRoadSurface` сохранён | нет | да |
| реальное изменение (6 новых домов, стадийные дороги) | пересоздаётся | по-прежнему пересоздаётся (1 уничтожено / 15 создано) |
| 3 холостых тика | 0 / 0 | 0 / 0 |
`tests/roads.test.mjs`: KNOWN ISSUE превращён в жёсткую проверку (0/0 + поверхность сохранена; если раскладка действительно изменилась — печатается NOTE, не провал) и добавлена
проверка «реальное изменение всё ещё пересобирает стадийные дороги». Прогон: roads — все `ok`, 0 FAIL, 0 ошибок консоли. Полный `npm test` не запускался.
Остаточный риск: подпись — контрольная сумма вершин, а не побайтовое сравнение; если когда-нибудь появится апгрейд, меняющий только материал текстурой (не цветом), он не вызовет пересборку.
Прогоны игры для этой части: 5 (диагностика стека, roads с первой версией защиты — провал, 2 диагностики, roads после исправления).
